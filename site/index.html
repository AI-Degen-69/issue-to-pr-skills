01 — The lifecycle

One command per phase. Skills load automatically.

Stations are narrow. Each one has an entry condition, a verification gate, and a plain-English report that ends with the single next step. No station simulates missing work.

See all skills →
Hover or tap a station dot for its simple explanation. The issue is always the star — machinery stays in tasks/plan.md.
02 — Why it works

AI agents default to the shortest path.
These skills close the shortcut.

🛡️

Proof before review

Station IV refuses to review unproven code. Station III refuses to ship without green tests or live browser proof.

🎯

Never invent

Missing reviewer? Skipped and recorded. Missing trigger ack? Reported as missing. No simulation, no assumption.

⚖️

Spec axis separately

“Follows every standard but does the wrong thing” is a different finding from “breaks standards”. They never merge.

⏱️

Quota-conscious

One focused review round per PR. On rate-limit, reuse prior evidence + delta check before fresh review.

How it feels in practice — one issue, start to finish

  1. 1. You paste an idea
    /i-create-issue add dark mode — the skill researches the repo, uses real paths with line numbers, and publishes a ready-for-agent issue.
  2. 2. You pick + plan
    /x-workflow-issue shows backlog grouped by domain. /ii-plan-issue 123 sizes it, locks CONSTRAINTS.md, writes tasks/plan.md slices.
  3. 3. It builds, reviews, merges
    /iii-build-plan auto TDDs each slice. /iv-review… proves then reviews, opens PR, triggers @coderabbitai. /v-babysit… merges. /vii-present… builds your showcase.
