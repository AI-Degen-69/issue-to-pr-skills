01 — What it is

Proactive vulnerability scanner and attack surface auditor

The security-reviewer persona operates with an adversary mindset. It inspects diffs for entry points, data flows, and configuration changes that could compromise application confidentiality, integrity, or availability.

Read
Source Analysis

Inspects entire authentication flows, token handling, and authorization middleware surrounding changes.

Grep
Secret & API Hunter

Scans the repository for regex patterns matching leaked tokens, API keys, private certs, and un-hashed passwords.

Glob
Config Discovery

Locates environment templates, CORS policies, security headers, Dockerfiles, and package manifests.

Bash
Audit Command

Executes non-destructive auditing tools such as npm audit --audit-level=high to surface CVEs.

Glossary for non-coders: OWASP Top 10: the industry-standard list of the 10 most critical security risks facing web applications. · SSRF: Server-Side Request Forgery, an attack where a server is tricked into requesting internal network data. · CVE: Common Vulnerabilities and Exposures, a public database of known software security flaws.

03 — Review checklist

Core vulnerability vectors inspected

Sourced directly from agents/security-reviewer.md, checks evaluate both user input defense and infrastructural boundaries.

CRITICAL — Secrets & Access Bypass

Flaws that instantly compromise infrastructure or allow unauthorized data exfiltration.

  • ✕ Hardcoded secrets: Tokens, AWS keys, Stripe secret keys, or database credentials in code.
  • ✕ Broken access controls: Routes lacking middleware checks or client-side-only permissions.
  • ✕ SQL / NoSQL injection: Unescaped string interpolation in database query builders.
  • ✕ SSRF vulnerabilities: Fetching arbitrary user-supplied URLs without protocol and IP allowlisting.
HIGH — Cryptography & Input Hygiene

Subtle flaws that allow session hijacking, weak hashing, or data corruption.

  • ✕ Insecure token storage: Storing JWTs or sensitive sessions in localStorage instead of httpOnly cookies.
  • ✕ Weak password hashing: Using MD5 or plain SHA-256 instead of bcrypt or argon2.
  • ✕ Missing schema validation: Accepting raw request bodies without Zod/Joi runtime validation.
  • ✕ Overly permissive CORS: Setting Access-Control-Allow-Origin: * alongside credentials.
MEDIUM — Headers & Misconfiguration

Missing defense-in-depth protective layers.

  • ✕ Missing security headers: Absence of Content-Security-Policy, HSTS, or X-Content-Type-Options.
  • ✕ Verbose error disclosure: Returning raw database stack traces directly in client responses.
  • ✕ Outdated dependencies: Unpinned packages with known high-severity vulnerabilities in package.json.
LOW — Audit Trails & Defense

Audit logging gaps and hygiene standards.

  • ✕ Missing auth logs: Failing to log failed authentication attempts or password reset requests.
  • ✕ Unsanitized debug logs: Logging full user request payloads containing email addresses or PII.

05 — When it runs

Real-world scenarios where security-reviewer engages

1. Adding user authentication

When creating login or signup routes, the reviewer verifies password hashing algorithms, session expiration limits, rate limiting, and secure cookie attributes.

2. Integrating external webhooks

When handling Stripe, GitHub, or third-party webhooks, it ensures cryptographic signature verification is performed prior to parsing or storing payloads.

3. File upload & asset handling

When allowing users to upload avatars or documents, it checks MIME-type validation, filename sanitization, size limits, and storage segregation.

06 — Output format

Structured finding anatomy & verdict

[CRITICAL] Potential SQL Injection in user search query
File: src/db/users.ts:88
Issue: User input is directly interpolated into a raw SQL query string via template literal.
Fix: Replace string interpolation with parameterized SQL query arguments ($1, $2).
// BAD: Interpolated string allows query escape
const query = `SELECT * FROM users WHERE name = '${userInput}'`;

// GOOD: Parameterized query safely escaped by driver
const query = 'SELECT * FROM users WHERE name = $1';
await db.query(query, [userInput]);

07 — Strict boundaries

What security-reviewer does NOT do

No automated patching

The reviewer reports vulnerabilities and provides suggested remediation snippets, but never directly modifies your source files or credentials.

Skips stylistic nits

Formatting, variable naming conventions, and cosmetic issues belong to code-reviewer or standard linters, not security.

Language-specific types

Deep TypeScript typing nuances and hook re-render mechanics are delegated to typescript-reviewer and react-reviewer.
