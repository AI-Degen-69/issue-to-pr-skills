01 — What it is

Specialist for type integrity and asynchronous pitfalls

The typescript-reviewer evaluates how types model domain invariants, guards against silent runtime exceptions, and prevents async race conditions before they enter the repository.

Read
Type Definition Context

Reads upstream interfaces, exported union types, and caller functions to verify contracts are obeyed.

Grep
Cast & Bypass Hunt

Searches for prohibited shortcuts: any, forced as unknown as T casts, and non-null assertions (!).

Glob
Project References

Finds relevant tsconfig.json and composite project reference configurations across monorepos.

Bash
Typecheck Command

Runs project-level type checks (e.g. npm run typecheck or tsc --noEmit) to verify compilation.

Glossary for non-coders: Floating Promise: an asynchronous operation started without an `await` or `.catch()`, which causes errors to vanish silently into the void. · Non-null Assertion (`!`): telling the compiler "trust me, this value is never null" without actually checking at runtime.

03 — Review checklist

The 4-tier TypeScript quality checklist

Sourced directly from agents/typescript-reviewer.md, focused on eliminating type blindness and unhandled asynchronous pitfalls.

CRITICAL — Dynamic Execution & Injection

Flaws that cause remote execution or severe server-side vulnerabilities.

  • ✕ Dynamic code execution: Using eval() or new Function() with user-supplied arguments.
  • ✕ Path traversal in Node: Unsanitized parameters passed to fs.readFile without path resolution validation.
  • ✕ Command injection: Spawning child processes with unvalidated user input via child_process.exec.
  • ✕ Prototype pollution: Deeply merging untrusted JSON objects without safe object containers.
HIGH — Type Safety & Async Correctness

Compromising TypeScript's guarantee or introducing runtime race conditions.

  • ✕ Unjustified any: Turning off the compiler. Require unknown with narrowing guards.
  • ✕ Non-null assertions (!): Masking potential undefined states without runtime null guards.
  • ✕ Floating promises: Calling async functions without await or .catch() error handlers.
  • ✕ forEach with async: Array.forEach does not await promises; operations execute out of order.
  • ✕ Weakening tsconfig: Turning off strict, noImplicitAny, or strictNullChecks.
MEDIUM — Performance & Error Modeling

Efficiency bottlenecks and imprecise error representations.

  • ✕ Sequential loop awaits: Awaiting independent async calls in loops instead of Promise.all().
  • ✕ Catching as any: In TS 4+, catch clauses should be typed as unknown and verified with instanceof Error.
  • ✕ Unnecessary type assertions: Casting variables to types they already possess.
LOW — Idiomatic Conventions

Code elegance and maintainability standards.

  • ✕ Explicit return types: Missing return types on public exported library interfaces.
  • ✕ Naming conventions: Enforcing PascalCase for types and camelCase for functions and variables.

05 — When it runs

Real-world scenarios where typescript-reviewer catches bugs

1. Async data loading loops

Developers often write items.forEach(async item => { await save(item); }), assuming it waits. The reviewer flags this and converts it to a safe for...of loop or Promise.all().

2. Silencing errors with `as any`

When dealing with complex API responses, developers sometimes force data as any. The reviewer stops this and introduces a discriminative union or Zod schema parser.

3. Optional chaining false comfort

Catching situations where user?.address!.street uses non-null assertions immediately after optional chaining, creating an immediate crash if user is undefined.

06 — Output format

Structured finding format & actionable code advice

[HIGH] Unhandled Promise in event listener (floating promise)
File: src/services/analytics.ts:34
Issue: Async function trackEvent() is invoked synchronously without await or error handler. Any network failure will trigger an unhandled rejection.
Fix: Await the promise or attach an explicit .catch() handler.
// BAD: Fire-and-forget without error handling
window.addEventListener('click', () => { trackEvent('click'); });

// GOOD: Explicitly catch and report errors
window.addEventListener('click', () => {
  void trackEvent('click').catch(err => logger.error('tracking failed', err));
});

07 — Strict boundaries

What typescript-reviewer does NOT do

React Hook Semantics

React dependency arrays, Hook rules, and JSX component accessibility are owned exclusively by react-reviewer.

Does Not Refactor

The agent never edits or rewrites files on disk. It produces diagnostic reports with proof and exact code remediation examples.

SQL & Query Plans

Even though TypeScript ORMs (Prisma, Drizzle) are written in TS, database indexing and N+1 query inspection belong to database-reviewer.
