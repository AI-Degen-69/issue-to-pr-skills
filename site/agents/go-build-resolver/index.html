01 · What it is

Rapid Go compilation triage and toolchain fixer

The go-build-resolver diagnoses compiler messages, interface discrepancies, and module synchronization errors. It isolates the exact missing import, incorrect type assertion, or unused identifier, patching only what is strictly required to restore a green build.

Read & Edit
Context & Patching

Reads the affected Go files, method signatures, and applies surgical line edits.

Bash
Compiler Execution

Runs go build ./..., go vet ./..., and go mod tidy.

Grep
Symbol Tracing

Searches package references, interface implementations, and export casing across directories.

Glob
Package Inventory

Finds all Go packages, internal modules, and generated files in the workspace.

Glossary for non-coders: go vet: An official Go tool that analyzes source code and flags suspicious, non-idiomatic constructs. · Interface Mismatch: In Go, types implement interfaces implicitly; missing one method breaks compilation. · go mod tidy: Reconciles module requirements with actual imports in source files.

03 · Repair playbook

Primary Go failure modes and surgical solutions

Sourced directly from agents/go-build-resolver.md, each pattern resolves the cause without modifying logic flow.

Types & Interface Contracts
  • → cannot use X as type Y: Resolve pointer/value mismatch or add explicit type conversion.
  • → X does not implement Y: Implement missing method with matching pointer or value receiver.
  • → multiple-value in single-value: Handle both returned values: result, err := fn().
Imports & Module Boundaries
  • → undefined: X: Add missing package import or fix exported identifier casing.
  • → import cycle not allowed: Extract shared interfaces/types into a dedicated leaf package.
  • → declared but not used: Remove dead assignment or discard explicitly with _.

Step-by-step Go error elimination cadence

  3. Step 3

    Surgical changes
  4. Step 4

  5. Step 5
    go test ./...

    Ensures no regressions were introduced by the repair.

    Pass verification
05 · Strict boundaries

What go-build-resolver does NOT do

No //nolint comments

Never silences compiler or linter errors by adding suppression directives without explicit approval.

No signature changes

Avoids changing public function signatures or exported struct fields unless unavoidable.

No speculative refactoring

Fixes the root cause of the error only; leaves working idiomatic or style decisions alone.
