01 · What it is

Rigorous memory safety, lifetime, and unsafe auditor

The rust-reviewer holds Rust PRs to the highest standard of idiomatic engineering. It flags unprincipled `.unwrap()` in production paths, requires explicit // SAFETY: comments for every unsafe block, catches blocking I/O inside asynchronous Tokio tasks, and eliminates unnecessary heap allocations.

Read
Source Analysis

Reads altered Rust files and callers across workspace crates to verify memory contracts.

Bash
Automated Tooling

Executes cargo clippy -- -D warnings, cargo audit, and cargo test.

Grep
Safety & Panic Scan

Searches for unhandled `.unwrap()`, raw pointer arithmetic, and missing SAFETY comments.

Glob
Workspace Scoping

Isolates modified crate members, Cargo.toml files, and integration tests in the diff.

Glossary for non-coders: Unsafe Rust: A mode that relaxes compiler checks to allow raw hardware access, requiring strict human proof. · Unwrap: Extracting a value that causes an immediate program crash if the value is empty or an error. · Async Blocking: Running long computations on async workers, which freezes other simultaneous operations.

03 · Inspection checklist

Structured priority review matrix

Sourced directly from agents/rust-reviewer.md, issues are strictly triaged into blocking vs advisory tiers.

CRITICAL: Safety & Errors
  • ✕ Unchecked unwrap(): Raw .unwrap() or .expect() in production paths.
  • ✕ Unsafe without comment: Missing // SAFETY: documenting safety invariants.
  • ✕ Silenced errors: Discarding results via let _ = result; on #[must_use] types.
  • ✕ Injection / Traversal: Unvalidated strings in commands or database queries.
HIGH: Ownership & Async
  • ! Unnecessary cloning: Calling .clone() solely to appease borrow checker without understanding.
  • ! Blocking in async: Using std::thread::sleep or blocking files in Tokio contexts.
  • ! Unbounded channels: Using unbounded channels without buffer limits or backpressure.
  • ! Poisoning ignored: Ignoring PoisonError returned from mutex locks.
MEDIUM: Efficiency & Idioms
  • i String vs &str: Taking owned String when borrowed &str suffices.
  • i Missing capacity: Missing Vec::with_capacity(n) when size is known.
  • i Clippy warnings: Silencing clippy warnings with unapproved #[allow(...)].
  • i Derive order: Out-of-order derives (Debug, Clone, PartialEq, Eq...).
04 · Decision Framework

Clear verdicts based on issue severity

APPROVE

Zero CRITICAL and zero HIGH issues found. Code is memory-safe, panic-free, and idiomatic.

WARNING

MEDIUM issues only (e.g. minor allocation tuning or derive order). Does not block shipping.

BLOCK

Any CRITICAL (unsafe without justification, unwrap in production) or HIGH (async blocking) halts merge.

05 · Strict boundaries

What rust-reviewer does NOT do

No code modifications

It is an auditor, not an editor. All required fixes are dispatched back to builder personas.

No formatting debates

Formatting is strictly settled by cargo fmt --check; never argues indentation or line wraps.

No subjective rewrites

Accepts diverse working patterns as long as memory safety, lifetime invariants, and performance hold.
