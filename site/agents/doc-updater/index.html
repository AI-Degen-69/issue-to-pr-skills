Agents / doc-updater Codemaps & Living Documentation

doc-updater

A documentation and architecture codemap specialist. Inspects code changes, generates living maps in docs/CODEMAPS/, and keeps README guides, API contracts, and usage examples perfectly synchronized with production code.

Dispatched by
Station VI
vi-close-pipeline & doc tasks

Execution model
Codemap Generator

01 · What it is

Automatic synchronization between code truth and written guides

Documentation rots when written by hand and neglected during refactoring. The doc-updater eliminates drift by generating codemaps directly from codebase ASTs, imports, exports, and schema definitions.

Read
AST & JSDoc

Extracts type interfaces, function docstrings, exported parameters, and environment schemas.

Write / Edit
Codemap Publishing

Writes clean Markdown codemaps under 500 lines per module with fresh timestamps and ASCII diagrams.

Grep
Reference Audit

Searches docs for renamed symbols, outdated paths, or stale command examples.

Bash
Doc Validation

Runs link checkers, doc generators, and code-snippet compilers to verify accuracy.

02 · Lifecycle placement

Active during post-build wrap-up and pipeline closeout

Ensures that before an issue closes and its branch is pruned, all documentation changes are committed alongside the code so external users and future agents have full context.

03 · Codemap layout

Structured repository maps

docs/CODEMAPS/
├── INDEX.md # High-level architecture and area catalog
├── frontend.md # UI components, routing, state stores, and layout primitives
├── backend.md # API endpoints, middleware pipelines, and controllers
├── database.md # Tables, schemas, relationships, indexes, and RLS policies
├── integrations.md # Third-party SDKs, webhook listeners, external APIs
└── workers.md # Background queues, event handlers, and scheduled crons
04 · Strict boundaries

What doc-updater does NOT do

No code logic edits

Does not alter executable code or business logic; it documents what was built.

No marketing prose

Focuses on technical clarity, accurate code references, and developer-first guides rather than marketing copy.

No bloated files

Enforces token efficiency with a strict limit under 500 lines per generated codemap file.
