01 · What it is

Expert evaluator for idiomatic Go and concurrency safety

The go-reviewer reviews code with the discerning eye of a veteran Go engineer. It enforces the idioms that make Go programs robust: early returns over nested ifs, proper error wrapping with %w, goroutine lifecycle management via contexts, and pre-allocation of slices in hot loops.

Read
Source Analysis

Reads altered Go files and their surrounding package contexts to trace callers.

Bash
Automated Checks

Executes go vet, staticcheck, and race-detector test runs.

Grep
Anti-pattern Scanning

Detects raw error discards (_ = fn()), mutex unlocks outside defer, and SQL concatenations.

Diff Scoping

Filters all repository changes strictly to modified Go packages and test suites.

Glossary for non-coders: Goroutine Leak: Starting background work that never stops because it was never notified to cancel, wasting memory. · Race Condition: When two threads read and write memory simultaneously without coordination, causing subtle corruption. · Error Wrapping: Preserving the original root cause error while adding human-readable breadcrumb context.

03 · Inspection checklist

Structured priority review matrix

Sourced directly from agents/go-reviewer.md, issues are strictly triaged into blocking vs advisory tiers.

CRITICAL: Security & Errors
  • ✕ Ignored Errors: Using _ to discard returned errors.
  • ✕ Missing Wrapping: return err without fmt.Errorf("...: %w", err).
  • ✕ SQL / Command Injection: Concatenating input into database or exec calls.
  • ✕ Uncontrolled Panics: Panicking for recoverable business errors.
HIGH: Concurrency & Idioms
  • ! Goroutine Leaks: Spawning goroutines without context cancellation.
  • ! Channel Deadlocks: Unbuffered channels sending without ready receivers.
  • ! Mutex Misuse: Forgetting defer mu.Unlock() immediately after lock.
  • ! Deep Nesting: Nested if/else blocks instead of idiomatic early returns.
MEDIUM: Efficiency & Style
  • i String Builder: Repeated + in loops instead of strings.Builder.
  • i Slice Capacity: Missing make([]T, 0, cap) for known item counts.
  • i Context First: Context parameter not positioned as the first argument.
  • i Table Tests: Unit tests not using table-driven slice structures.
04 · Decision Framework

Clear verdicts based on issue severity

APPROVE

Zero CRITICAL and zero HIGH issues found. Code is idiomatic, leak-free, and safe for production.

WARNING

Only MEDIUM issues (e.g. minor allocation tuning or naming suggestions). Does not block ship.

BLOCK

Any CRITICAL (security flaw, discarded error) or HIGH (goroutine leak, deadlock) issue halts the PR.

05 · Strict boundaries

What go-reviewer does NOT do

No code modifications

It is an auditor, not an editor. All required fixes are dispatched back to builder personas.

No bike-shedding formatting

Formatting is strictly handled by gofmt; the reviewer never debates indentation or braces.

No personal style mandates

Enforces official Go team and Uber Go style guides rather than arbitrary personal preferences.
