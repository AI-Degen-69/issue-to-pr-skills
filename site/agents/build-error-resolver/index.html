01 · What it is

Rapid error triage and compiler repair agent

The build-error-resolver operates on a single principle: get the build green as quickly as possible with the smallest valid diff. It treats compiler errors as puzzles with exact minimal solutions, refusing speculative improvements.

Read
Context Extraction

Reads the exact lines and surrounding scope triggering compilation errors.

Edit
Surgical Patching

Applies tight type annotations, null guards, or import corrections without touching logic.

Bash
Compiler Feedback

Runs npx tsc --noEmit and npm run build to verify clean exit.

Grep
Symbol Discovery

Traces missing types, re-exports, and declaration files across the project workspace.

Glossary for non-coders: Type Error: A discrepancy where code expects one format of data (like a number) but receives another (like text). · Compilation: The automated process translating source code into runnable executable programs or bundles. · Surgical Diff: Changing only the 1 or 2 characters required to fix a failure, leaving the rest intact.

03 · Repair playbook

Primary failure modes and surgical solutions

Sourced directly from agents/build-error-resolver.md, each pattern resolves the cause without modifying logic flow.

Type Inference & Null Safety
  • → Implicit any: Add explicit parameter or variable type annotation.
  • → Possibly undefined: Insert optional chaining ?. or explicit truthiness guard.
  • → Property does not exist: Update interface contract or cast when narrowing union types.
Imports & Module Resolution
  • → Cannot find module: Correct relative paths, check tsconfig.json path aliases, or add missing package.
  • → Named vs default export: Align import syntax with target module declaration.
  • → Missing type declarations: Install @types/* devDependencies.

05 · Strict boundaries

What build-error-resolver does NOT do

No feature additions

Never introduces new logic, helper functions, or business behavior while repairing build failures.

No architectural redesigns

Does not rewrite module boundaries or swap libraries. It fixes errors in the code as written.

No cosmetic renaming

Leaves variable names and styling alone unless a collision directly causes the compiler error.
