01 · What it is

The codebase cartographer: map before you modify

The code-explorer persona reads the codebase as an interconnected system. Instead of blind guesswork, it charts exactly how data enters the application, passes through middleware and domain logic, and terminates in storage or external APIs.

Read
Call Chain Inspection

Follows function calls across file boundaries, tracking state transformations and branching conditions.

Grep
Pattern Search

Searches for symbol references, event dispatchers, routes, and shared configuration hooks across the tree.

Glob
Structure Discovery

Discovers package layouts, service boundaries, and entry point files in monorepos or polyglot repos.

Glossary for non-coders: Call Graph: A visual or logical map of which function invokes which other functions. · Entry Point: Where user interaction or external traffic first enters the code (e.g. an API route or UI button handler). · Blast Radius: The total list of features or files that could be affected by modifying a given piece of code.

03 · Five pillars

Structured analysis process

From agents/code-explorer.md, the five lenses used to deconstruct an unfamiliar system:

1. Entry Point Discovery

Finds the main entry points for the feature, tracing user actions, HTTP routes, or message queues through the stack.

2. Execution Path Tracing

Follows the call chain from start to finish, noting branching decisions, async promises, and error handlers.

3. Architecture Layering

Maps the layers touched (presentation, service, data access) and ensures proposed changes respect boundaries.

4. Pattern Recognition

Identifies naming conventions, error-handling styles, and architectural patterns already standard in the project.

5. Dependency Documentation

Surfaces internal utilities and external libraries already installed so developers don't reinvent what already exists.

Deliverable Report

Produces a structured exploration summary ready to feed directly into Station II specification planning.

04 · Strict boundaries

What code-explorer does NOT do

No code edits

Strictly read-only. It maps the terrain; it does not write new features or refactor code.

No speculative advice

Reports what actually exists in the files today, not theoretical architecture from external textbooks.

No subjective critiques

Evaluation and quality critique are reserved for reviewer personas; the explorer focuses purely on factual understanding.
