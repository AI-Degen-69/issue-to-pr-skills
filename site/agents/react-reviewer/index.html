01 — What it is

Dedicated inspector for React lifecycle, hooks, and UI safety

The react-reviewer inspects component rendering loops, ensures accessibility compliance, and audits React-specific security flaws like server action leaks or dangerous HTML injection.

Read
Component Scope

Reads full component tree, provider wrappers, and parent context to understand re-render chains.

Grep
Hook & Prop Patterns

Scans for anti-patterns: dangerouslySetInnerHTML, missing key attributes, and inline arrow handlers in loops.

Glob
Asset Discovery

Discovers component design system files, CSS modules, Tailwind configs, and shared UI primitives.

Bash
Lint & Hook Audit

Executes ESLint with eslint-plugin-react-hooks to catch dependency omissions.

Glossary for non-coders: Stale Closure: when a React hook remembers an old value of a state variable instead of the current one, causing subtle bugs. · RSC: React Server Components, which run only on the server and must never leak client interactivity or secrets. · a11y (Accessibility): designing user interfaces so people with screen readers and keyboards can navigate effortlessly.

03 — Review checklist

The 4-tier React checklist

Sourced directly from agents/react-reviewer.md, focused strictly on React-specific vulnerabilities, performance bottlenecks, and accessibility.

CRITICAL — React Security

Flaws allowing code execution in client browsers or secret exposure.

  • ✕ Unsanitized dangerouslySetInnerHTML: Rendering untrusted content without DOMPurify sanitization.
  • ✕ Unvalidated URL schemes: Allowing javascript: or data: URLs in href or src props.
  • ✕ Server Action without input schema: `"use server"` functions accepting raw parameters without Zod validation.
  • ✕ Secret in client bundle: Exposing backend API keys or database strings via NEXT_PUBLIC_* or VITE_*.
HIGH — Hook Correctness & Lifecycle

Violating React invariants that cause infinite loops, desynchronized state, or memory leaks.

  • ✕ Conditional hook calls: Placing useState or useEffect inside if-statements or loops.
  • ✕ Missing hook dependencies: Omitting functions or variables from useEffect / useCallback dependency arrays.
  • ✕ State mutation during render: Calling setState directly in the component body instead of an effect or handler.
  • ✕ Array index as key: Using list indices as React keys on items that can be sorted, added, or removed.
MEDIUM — Render Performance & Boundaries

Wasted render cycles and jarring layout shifts.

  • ✕ Derived state in useEffect: Computing state in an effect that could be calculated directly during render.
  • ✕ Missing Suspense boundaries: Data-fetching components that block the entire page without fallback skeletons.
  • ✕ Unmemoized heavy transforms: Re-filtering 10,000 items on every render without useMemo.
LOW — Accessibility (a11y) & Clean HTML

Keyboard navigation and assistive technology compatibility.

  • ✕ Non-interactive clickables: <div onClick> without role="button" or keyboard event listeners.
  • ✕ Missing form labels: Input fields lacking associated <label> elements or aria-label tags.

05 — When it runs

Real-world scenarios where react-reviewer engages

1. Infinite re-render prevention

When an effect triggers a state update that immediately triggers the same effect again, the reviewer catches the missing dependency or condition before it crashes user browsers.

2. Next.js Server Action audit

When someone adds a `"use server"` function, the reviewer confirms that permissions and authentication are checked on the server side, rather than trusting client-passed credentials.

3. Accessible interactive modal

When a new modal dialog is created, it verifies focus trapping, escape key listeners, and aria-modal attributes so keyboard users aren't locked out.

06 — Output format

Structured finding format & actionable remediation

[HIGH] Stale closure in useEffect interval
File: src/components/Timer.tsx:18
Issue: setInterval reads `count` from closure without count in dependency array, causing timer to freeze after first tick.
Fix: Use functional state updater `setCount(prev => prev + 1)` or add count to dependencies.
// BAD: Stale closure captures initial value 0
useEffect(() => {
  const id = setInterval(() => setCount(count + 1), 1000);
  return () => clearInterval(id);
}, []);

// GOOD: Functional update accesses latest state cleanly
useEffect(() => {
  const id = setInterval(() => setCount(prev => prev + 1), 1000);
  return () => clearInterval(id);
}, []);

07 — Strict boundaries

What react-reviewer does NOT do

Generic TypeScript rules

Non-React TypeScript questions (union discrimination, Node async loops, TS compiler flags) are owned by typescript-reviewer.

Does not rewrite components

The reviewer reports findings with code examples, but never touches source files or auto-applies diffs.

Visual graphic design

Subjective aesthetic decisions (color palettes, font choices) are outside scope — focus remains strictly on accessibility, rendering bugs, and security.
