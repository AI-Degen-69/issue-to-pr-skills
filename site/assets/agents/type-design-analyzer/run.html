Overall: weak — illegal states fully representable. The business rule "an account is exactly one of trial / active / suspended" is real and matters (billing depends on it), but the type states it only in a comment. Any string — "ACTIVE ", "suspend", a typo — compiles, flows past every call site, and only explodes at runtime in billing logic.
Suggestion 1: replace the string with a union — status: "trial" | "active" | "suspended". The compiler then enforces the invariant at every assignment and every switch is exhaustiveness-checked.
Suggestion 2: make the illegal state unrepresentable — suspendedAt should be required exactly when status is "suspended"; model it as a discriminated union so a suspended account without a timestamp cannot exist.
Suggestion 3: if values arrive from outside (API), parse at the boundary — parseStatus(raw: string): AccountStatus — so untrusted strings are rejected once, at the edge, instead of being trusted everywhere.
